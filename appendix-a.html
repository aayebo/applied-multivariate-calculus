Appendix A. Introduction to R and RStudio

Learning. After completing this appendix, you should be able to install and navigate R and RStudio; write, save, and run reproducible scripts; work with vectors, matrices, functions, and data frames; construct two- and three-dimensional mathematical visualizations; carry out symbolic-style derivations where appropriate and reliable numerical computations; solve the representative calculus problems encountered in Chapters 1–8; diagnose common errors; and communicate computational results clearly.

Why R belongs in a multivariable calculus textbook

R is a programming language and computational environment designed for statistical computing and graphics, but its vectorized operations, matrix algebra, numerical solvers, and visualization tools also make it useful for multivariable calculus. The purpose of this appendix is not to replace mathematical reasoning with software. In every chapter, we first define the mathematical object, derive the needed formula, and only then use R to compute, verify, visualize, or extend the result. A numerical answer does not establish a theorem: the proof or analytical justification remains a separate task.

What R does well.

R handles vectors and matrices, numerical optimization, quadrature, ordinary differential equations through packages, tabular data, and reproducible graphics. Its base installation supports much of this appendix. Some advanced features require separately installed packages; these are identified explicitly. Unlike a computer algebra system, base R does not generally return symbolic antiderivatives or exact symbolic derivatives.

Installing R and RStudio

Two related but different programs

R is the language and execution engine. RStudio is an integrated development environment (IDE) that provides a script editor, Console, environment browser, plot viewer, and file/project management. Install R before installing RStudio Desktop. RStudio is convenient, but every base-R example here can also run in an ordinary R session.

A reliable setup procedure

  1. Obtain a current release of R from the Comprehensive R Archive Network (CRAN): https://cran.r-project.org/. Choose the installer appropriate for Windows, macOS, or Linux and follow its instructions.

  2. Obtain RStudio Desktop from Posit’s official download site: https://posit.co/download/rstudio-desktop/. Install and launch it after R is installed.

  3. In the Console, enter R.version.string and getwd(). The first identifies your installed R version; the second prints the current working directory.

  4. Create a new RStudio Project for this book, for example multivariable-calculus-r. Create subfolders named scripts, data, figures, and results.

  5. Save a script called scripts/first_steps.R; enter 2 + 3 and run the line. Save the script and verify that the Console displays 5.

Software menus and interface arrangements change across versions. The conceptual workflow—write code in a script, run it in the Console, inspect results, and save reproducible outputs—is more important than the precise position of an icon.

Understanding the RStudio interface

In a typical RStudio layout, the Source pane holds scripts, the Console executes commands, the Environment/History pane shows objects and prior commands, and the Files/Plots/Packages/Help pane supports navigation and output. Pane placement can be customized. The > prompt means R is ready; a + prompt usually means an expression is incomplete, often because a parenthesis, quotation mark, or brace has not been closed. Press Escape to abandon an incomplete expression and inspect the previous lines.

Checkpoint. Create an RStudio Project and run getwd(), R.version.string, and sessionInfo(). Explain which command identifies your project location, which identifies the R version, and which records package and platform information useful for reproducibility.

Writing and running a reproducible script

A script is a plain-text file containing R commands. It is preferable to a long sequence of unsaved Console entries because it documents the computation and allows another reader to reproduce it.

RDownload
# scripts/first_steps.R
rm(list = ls())               # optional for a fresh teaching session
radius <- 3
height <- 8
volume <- pi * radius^2 * height
cat("Cylinder volume:", round(volume, 3), "cubic units\n")

The assignment operator <- stores a value. R also accepts = for assignment in many contexts, but this book uses <- consistently. Comments begin with #. The cat() function writes formatted text; round() controls displayed precision. Clearing the workspace with rm(list = ls()) is optional and should not substitute for designing a script that runs from a fresh session.

Files, folders, and projects

Keep data and output paths relative to the project root: read.csv("data/measurements.csv") rather than an absolute path that works only on one computer. getwd() reports the current directory; list.files() lists its contents. Avoid relying on manually changing directories with setwd() inside shared scripts. Save code and results separately so a figure can be regenerated without searching through unrelated files.

R syntax and mathematical arithmetic

Basic operators and precedence

Operation R syntax Mathematical meaning
Addition, subtraction a+b, a-b \(a+b\), \(a-b\)
Multiplication, division a*b, a/b \(ab\), \(a/b\)
Exponentiation a^b \(a^b\)
Square root sqrt(a) \(\sqrt a\)
Natural logarithm log(a) \(\ln a\)
Trigonometry sin(t), cos(t) radians
Equality test a == b logical comparison
Matrix product A %*% B \(AB\)

Use parentheses whenever precedence might be ambiguous. For example, (x+y)^2 is different from x+y^2. R uses radians in trigonometric functions; convert degrees with theta * pi / 180. Values such as pi, Inf, NaN, and NA have distinct meanings: mathematical constant, infinity, undefined numerical result, and missing value.

RDownload
theta_deg <- 60
theta <- theta_deg * pi / 180
sin(theta)
cos(theta)
all.equal(sin(theta)^2 + cos(theta)^2, 1)

Floating-point calculations generally produce approximations. Compare computed values using a tolerance, not always ==. The expression all.equal() returns TRUE when values agree within its tolerance, or a descriptive message otherwise. For programmatic tests, isTRUE(all.equal(a,b)) is useful.

Object types and inspection

An R object can be numeric, integer, logical, character, complex, a vector, a matrix, a list, or a data frame. Use class(x), typeof(x), length(x), str(x), and summary(x) to understand it. R is case-sensitive: velocity and Velocity are different names.

Vectors: the foundation of computational calculus

Creating and indexing vectors

RDownload
v <- c(2, -1, 4)
w <- c(1, 3, -2)
v[1]                      # first component: R indexes from 1
v[2:3]                    # second and third components
length(v)                 # number of entries
v + w                     # componentwise addition
3 * v                     # scalar multiplication
sum(v * w)                # dot product
sqrt(sum(v^2))            # Euclidean norm

R’s c() combines values into a vector. Indexing starts at 1, unlike Python. For a vector \(\boldsymbol{v}=(v_1,v_2,v_3)\), the Euclidean norm is \(\|\boldsymbol{v}\|=\sqrt{v_1^2+v_2^2+v_3^2}\) and the dot product is \(\boldsymbol{v}\cdot\boldsymbol{w}=\sum_i v_iw_i\).

The cross product in three dimensions

Base R has no dedicated general cross-product operator, so we can define one using the determinant formula.

RDownload
cross3 <- function(a, b) {
  stopifnot(length(a) == 3, length(b) == 3)
  c(a[2]*b[3] - a[3]*b[2],
    a[3]*b[1] - a[1]*b[3],
    a[1]*b[2] - a[2]*b[1])
}
a <- c(1, 2, 0)
b <- c(0, 1, 3)
cross3(a, b)
sum(cross3(a, b) * a)    # zero: orthogonality

For the displayed vectors, \(\boldsymbol{a}\times\boldsymbol{b}=(6,-3,1)\). Verify that its dot product with each original vector is zero. Geometrically, \(\|\boldsymbol{a}\times\boldsymbol{b}\|\) equals the parallelogram area spanned by \(\boldsymbol{a}\) and \(\boldsymbol{b}\).

Recycling: an important source of errors

R sometimes repeats elements of a shorter vector during arithmetic. Thus c(1,2,3,4) + c(10,20) produces a result by recycling. This can be useful but can also conceal a mathematical mistake. Before combining vectors that represent geometric objects, check that their dimensions agree using stopifnot(length(a)==length(b)).

Matrices, determinants, and linear systems

RDownload
A <- matrix(c(2, 1, 1, 3), nrow = 2, byrow = TRUE)
b <- c(5, 7)
A
nrow(A); ncol(A)
t(A)                       # transpose
det(A)                     # determinant
solve(A, b)                # solve A x = b
A %*% solve(A, b)          # verify solution

R fills matrices by columns unless byrow=TRUE. Elementwise multiplication uses A*B; matrix multiplication uses A %*% B. The function solve(A,b) is generally preferable to explicitly forming solve(A) %*% b when solving \(A\boldsymbol{x}=\boldsymbol{b}\). A near-singular matrix may produce unstable numerical results even if the syntax is correct. Use kappa(A) to inspect conditioning.

Eigenvalues and the Hessian

For a twice-differentiable function \(f(x,y)\), the Hessian collects second partial derivatives. Its eigenvalues help classify a stationary point when the Hessian is nonsingular.

RDownload
H <- matrix(c(4, 1, 1, 6), nrow = 2, byrow = TRUE)
eigen(H)$values

Both eigenvalues are positive, so this symmetric Hessian is positive definite. If it is the Hessian at a stationary point, the second-derivative test establishes a strict local minimum. This conclusion assumes the usual differentiability conditions; an arbitrary positive-definite matrix alone does not establish where a function is stationary.

Sequences, grids, and vectorized evaluation

RDownload
x <- seq(-2, 2, length.out = 101)
y <- seq(-2, 2, length.out = 101)
z <- x^2 + 2*x + 1
head(z)
G <- expand.grid(x = seq(-1, 1, by = 0.5),
                 y = seq(-1, 1, by = 0.5))
G$height <- G$x^2 + G$y^2
head(G)

seq() constructs a sequence; rep() repeats values; expand.grid() enumerates Cartesian combinations. Vectorization evaluates a function at many points without an explicit loop when operations naturally act elementwise. This is especially useful for level curves, surfaces, and numerical integration.

Functions, conditionals, and iteration

Writing a mathematical function

RDownload

Conditional statements and loops

RDownload

Plotting a parametrized curve

These two plots show complementary projections, not a three-dimensional rendering. When presenting a 3D view, distinguish the geometric object from its 2D projection and avoid treating perspective distortion as a quantitative measurement.

Numerical differentiation and the meaning of step size

The centered finite-difference approximation to \(f'(x)\) is \[D_hf(x)=\frac{f(x+h)-f(x-h)}{2h}.\] For sufficiently smooth \(f\), the truncation error is \(O(h^2)\), but floating-point cancellation can dominate when \(h\) is extremely small. Thus smaller \(h\) does not always mean a more accurate result.

RDownload
centered_derivative <- function(f, x, h = 1e-5) {
  (f(x + h) - f(x - h)) / (2*h)
}
centered_derivative(sin, pi/3)
cos(pi/3)                 # analytical comparison

For a function of two variables, hold one coordinate fixed when approximating a partial derivative.

RDownload
f <- function(x, y) x^2*y + sin(x*y)
h <- 1e-5
fx <- (f(1+h, 2) - f(1-h, 2))/(2*h)
fy <- (f(1, 2+h) - f(1, 2-h))/(2*h)
cat("Approximate gradient:", fx, fy, "\n")

Analytically, \(f_x=2xy+y\cos(xy)\) and \(f_y=x^2+x\cos(xy)\). Evaluate these formulas at \((1,2)\) and compare with the numerical approximations. This is the recommended workflow: derive first, compute second, verify third.

Gradients, Jacobians, and tangent-plane approximations

For \(f:\mathbb{R}^2\to\mathbb{R}\), the tangent-plane approximation at \((a,b)\) is \[L(x,y)=f(a,b)+f_x(a,b)(x-a)+f_y(a,b)(y-b).\]

RDownload
f <- function(x, y) x^2 + x*y + 2*y^2
a <- 1; b <- -1
fx <- function(x, y) 2*x + y
fy <- function(x, y) x + 4*y
L <- function(x, y) {
  f(a, b) + fx(a, b)*(x-a) + fy(a, b)*(y-b)
}
c(exact = f(1.1, -0.9), linear = L(1.1, -0.9))

For a vector-valued map \(\boldsymbol{F}=(F_1,F_2)\), the Jacobian is the matrix of first partial derivatives. Its determinant describes local signed area scaling where the map is differentiable.

RDownload
# F(r,theta) = (r*cos(theta), r*sin(theta))
polar_J <- function(r, theta) {
  matrix(c(cos(theta), -r*sin(theta),
           sin(theta),  r*cos(theta)),
         nrow = 2, byrow = TRUE)
}
det(polar_J(2, pi/4))     # equals r = 2

Optimization with R

One-variable optimization

optimize() searches for a minimum or maximum of a one-variable function over a specified interval. It is a numerical procedure, not a substitute for examining endpoints and proving a global claim.

RDownload
g <- function(x) (x - 2)^2 + 1
optimize(g, interval = c(-5, 5))

Unconstrained optimization in several variables

RDownload
objective <- function(p) {
  x <- p[1]; y <- p[2]
  (x - 1)^2 + 2*(y + 2)^2
}
gradient <- function(p) {
  c(2*(p[1] - 1), 4*(p[2] + 2))
}
fit <- optim(par = c(0, 0), fn = objective,
             gr = gradient, method = "BFGS")
fit$par
fit$value
fit$convergence            # zero typically indicates convergence

The analytical minimizer is \((1,-2)\) and the minimum is \(0\). Compare the numerical output with these values. optim() offers multiple algorithms; their suitability depends on differentiability, constraints, scaling, and initial values.

Constrained optimization by reducing the dimension

Suppose \(x+y=6\) and \(x,y\ge0\), and minimize \(x^2+2y^2\). Substituting \(y=6-x\) reduces the problem to one variable on \(0\le x\le6\).

RDownload
q <- function(x) x^2 + 2*(6-x)^2
answer <- optimize(q, c(0, 6))
x_star <- answer$minimum
y_star <- 6 - x_star
c(x = x_star, y = y_star, objective = answer$objective)

The Lagrange-multiplier equations yield \(x=4\), \(y=2\). Always examine whether a numerical optimum satisfies the original constraints. General nonlinear constraints may require a specialist package; do not treat unconstrained optim() as a constrained solver.

Numerical integration: one dimension to several

Base R quadrature

RDownload
integrate(function(x) x^2, lower = 0, upper = 1)

The exact answer is \(1/3\). The integrate() function uses adaptive numerical quadrature; the result includes an error estimate, but numerical error estimates are not mathematical proofs of exactness.

An iterated double integral

Consider \(\int_0^1\int_0^x (x+y)\,dy\,dx\). Its inner integral is \(\tfrac32x^2\) and its exact value is \(1/2\).

RDownload
inner <- function(x) {
  vapply(x, function(xx) {
    integrate(function(y) xx + y, 0, xx)$value
  }, numeric(1))
}
integrate(inner, 0, 1)$value

The use of vapply() ensures the inner function can accept a vector of outer quadrature points, as integrate() requires. An integrand and its integration region must be specified separately and precisely.

Polar-coordinate integration

For a disk of radius \(R\), the area integral becomes \[\iint_{x^2+y^2\le R^2}1\,dA =\int_0^{2\pi}\int_0^R r\,dr\,d\theta=\pi R^2.\]

RDownload
R <- 2
area <- integrate(function(r) 2*pi*r, 0, R)$value
c(numerical = area, exact = pi*R^2)

The factor \(r\) is the absolute Jacobian determinant. Omitting it is a common error when changing coordinates.

Monte Carlo integration and uncertainty

For uniformly sampled \((X_i,Y_i)\) in the unit square, an estimator of \(\iint_{[0,1]^2}f(x,y)\,dA\) is the sample mean of \(f(X_i,Y_i)\).

RDownload
set.seed(2026)
n <- 100000
x <- runif(n); y <- runif(n)
values <- x^2 + y^2
estimate <- mean(values)
mc_se <- sd(values)/sqrt(n)
c(estimate = estimate, SE = mc_se, exact = 2/3)

The Monte Carlo standard error measures sampling variability under the stated sampling design; it is not a guarantee about every random run. Recording the seed makes the demonstration reproducible.

Vector fields, circulation, and flux

For \(\boldsymbol{F}(x,y)=(-y,x)\) on the unit circle \(\boldsymbol{r}(t)=(\cos t,\sin t)\), \(0\le t\le2\pi\), we have \(\boldsymbol{r}'(t)=(-\sin t,\cos t)\) and \(\boldsymbol{F}(\boldsymbol{r}(t))\cdot\boldsymbol{r}'(t)=1\). Therefore the circulation is \(2\pi\).

RDownload
integrand <- function(t) {
  x <- cos(t); y <- sin(t)
  Fx <- -y; Fy <- x
  dx <- -sin(t); dy <- cos(t)
  Fx*dx + Fy*dy
}
c(numerical = integrate(integrand, 0, 2*pi)$value,
  exact = 2*pi)

The planar scalar curl is \(\partial F_y/\partial x-\partial F_x/\partial y=2\). Green’s theorem gives the same circulation as \(\iint_D2\,dA=2\pi\). The orientation is counterclockwise; reversing the orientation changes the sign.

Flux across a circle

For \(\boldsymbol{G}(x,y)=(x,y)\), the outward unit normal on the unit circle is \((\cos t,\sin t)\) and \(ds=dt\). The outward flux is \(2\pi\), consistent with the divergence theorem because \(\nabla\cdot\boldsymbol{G}=2\).

RDownload
flux_integrand <- function(t) {
  nx <- cos(t); ny <- sin(t)
  Gx <- cos(t); Gy <- sin(t)
  Gx*nx + Gy*ny
}
integrate(flux_integrand, 0, 2*pi)$value

Metrics, coordinate geometry, and geodesics

In Chapter 7, the unit sphere with coordinates \((\theta,\phi)\) has line element \(ds^2=d\theta^2+\sin^2\theta\,d\phi^2\) where \(\theta\) is colatitude. Thus the metric matrix is \[g(\theta,\phi)=\begin{pmatrix}1&0\\0&\sin^2\theta\end{pmatrix}.\]

RDownload
sphere_metric <- function(theta) {
  matrix(c(1, 0, 0, sin(theta)^2),
         nrow = 2, byrow = TRUE)
}
sphere_metric(pi/3)
det(sphere_metric(pi/3))   # sin(theta)^2

The coordinate singularities at the poles are not physical singularities of the sphere. The metric determinant vanishes at \(\theta=0,\pi\) because these coordinates cease to be regular there.

Great-circle distance

For unit vectors \(\boldsymbol{u}\) and \(\boldsymbol{v}\) representing points on a sphere of radius \(R\), the central angle is \(\alpha=\arccos(\boldsymbol{u}\cdot\boldsymbol{v})\) after clamping numerical roundoff to \([-1,1]\). The shorter great-circle distance is \(R\alpha\).

RDownload
great_circle <- function(u, v, radius = 1) {
  u <- u/sqrt(sum(u^2)); v <- v/sqrt(sum(v^2))
  d <- sum(u*v)
  radius * acos(max(-1, min(1, d)))
}
great_circle(c(1,0,0), c(0,1,0), radius = 6371)

The example gives a quarter-circumference distance of \(6371\pi/2\) kilometers when the illustrative Earth radius is \(6371\) km. A spherical approximation does not capture ellipsoidal Earth geometry or the details of actual travel routes.

Numerical solutions of differential equations

Euler’s method from first principles

For \(y'(t)=f(t,y)\), Euler’s method advances \(y_{n+1}=y_n+h f(t_n,y_n)\). The following implementation solves \(y'=-y\) with \(y(0)=1\).

RDownload
h <- 0.05
N <- 20
t <- seq(0, N*h, by = h)
y <- numeric(N+1)
y[1] <- 1
for (k in 1:N) {
  y[k+1] <- y[k] - h*y[k]
}
max(abs(y - exp(-t)))
plot(t, y, type = "b", xlab = "t", ylab = "y(t)")
lines(t, exp(-t), lty = 2)

The exact solution is \(e^{-t}\). This first-order method is pedagogically transparent but not always the best method for high-accuracy or stiff systems. For more advanced ODE work, the separately installed deSolve package provides established numerical solvers.

Finite differences for the heat equation

The one-dimensional heat equation is \[u_t=\kappa u_{xx},\qquad 0<x<L,\quad t>0,\] with prescribed initial and boundary conditions. On a uniform grid, the forward-time, centered-space method is \[u_i^{n+1}=u_i^n+\lambda(u_{i-1}^n-2u_i^n+u_{i+1}^n),\qquad \lambda=\frac{\kappa\Delta t}{\Delta x^2}.\] For the standard explicit scheme with constant diffusivity and Dirichlet boundaries, choose \(0<\lambda\le1/2\) for stability.

RDownload
L <- 1; kappa <- 0.1
nx <- 51
x <- seq(0, L, length.out = nx)
dx <- x[2] - x[1]
lambda <- 0.4
dt <- lambda*dx^2/kappa
nt <- 100
u <- sin(pi*x)
u[1] <- 0; u[nx] <- 0
for (step in 1:nt) {
  old <- u
  u[2:(nx-1)] <- old[2:(nx-1)] + lambda*(
    old[1:(nx-2)] - 2*old[2:(nx-1)] + old[3:nx])
  u[1] <- 0; u[nx] <- 0
}
time <- nt*dt
exact <- exp(-kappa*pi^2*time)*sin(pi*x)
cat("Maximum absolute error:", max(abs(u-exact)), "\n")
plot(x, u, type = "l", xlab = "Position", ylab = "u(x,t)")
lines(x, exact, lty = 2)

This code explicitly copies the old time level before updating interior nodes, avoiding the mistake of mixing old and new values in a single explicit step. To study convergence, reduce \(\Delta x\) and adjust \(\Delta t\) to preserve a stable value of \(\lambda\). Check both numerical error and the physical boundary conditions.

A validation checklist

Before accepting a numerical result, verify that the input dimensions and units are correct; evaluate a simple case with a known answer; compare against an independent mathematical method; inspect signs and orientation; vary discretization or tolerance; and explain any remaining approximation error. A graph is useful evidence of behavior but does not establish an identity or guarantee accuracy.

RDownload
check_close <- function(actual, expected, tol = 1e-7) {
  stopifnot(is.numeric(actual), is.numeric(expected))
  stopifnot(length(actual) == length(expected))
  stopifnot(all(is.finite(actual)), all(is.finite(expected)))
  stopifnot(max(abs(actual - expected)) < tol)
  invisible(TRUE)
}
check_close(sum(c(1,2,3)*c(4,5,6)), 32)

Communicating mathematical results professionally

Computational output should distinguish exact mathematics from numerical estimates, use consistent units, and avoid excessive digits. The following code prints a compact interpretation.

RDownload
value <- integrate(function(x) x^2, 0, 1)$value
exact <- 1/3
cat("Integral of x^2 on [0,1]\n")
cat("  Numerical estimate:", sprintf("%.8f", value), "\n")
cat("  Exact value:      1/3\n")
cat("  Absolute error:  ", sprintf("%.2e", abs(value-exact)),
    "\n")

sprintf() creates consistently formatted numbers; cat() combines narrative and results; \n starts a new line. Use \n\n to separate paragraphs in a longer console report. The code itself, input values, and package versions should accompany a reported result so another reader can reproduce it.

Extended worked laboratory 1: vectors, planes, and projection

A three-dimensional displacement is \(\boldsymbol{d}=(4,-2,5)\) and a plane has normal \(\boldsymbol{n}=(2,1,-2)\). The scalar component of \(\boldsymbol{d}\) in the normal direction is \(\boldsymbol{d}\cdot\widehat{\boldsymbol{n}}\), and the vector projection is \((\boldsymbol{d}\cdot\boldsymbol{n}/\|\boldsymbol{n}\|^2)\boldsymbol{n}\). The component tangent to the plane is the difference between \(\boldsymbol{d}\) and its normal projection.

RDownload
d <- c(4, -2, 5)
n <- c(2, 1, -2)
normal_component <- sum(d*n)/sqrt(sum(n^2))
projection <- (sum(d*n)/sum(n^2))*n
tangent_component <- d - projection
cat("Normal scalar component:", normal_component, "\n")
cat("Normal projection:", projection, "\n")
cat("Tangential component:", tangent_component, "\n")
stopifnot(abs(sum(tangent_component*n)) < 1e-10)
stopifnot(max(abs(projection+tangent_component-d)) < 1e-10)
Interpretation.

The two components are orthogonal, and their sum recovers the original displacement. A useful diagnostic is to test these geometric identities rather than checking only a single decimal answer. For a plane through \(\boldsymbol{p}_0\), the equation is \(\boldsymbol{n}\cdot(\boldsymbol{x}-\boldsymbol{p}_0)=0\); the normal direction does not depend on the choice of \(\boldsymbol{p}_0\).

Extended worked laboratory 2: curvature of a space curve

For the helix \(\boldsymbol{r}(t)=(a\cos t,a\sin t,bt)\), the first two derivatives are \(\boldsymbol{r}'=(-a\sin t,a\cos t,b)\) and \(\boldsymbol{r}''=(-a\cos t,-a\sin t,0)\). Its curvature is \[\kappa(t)=\frac{\|\boldsymbol{r}'(t)\times\boldsymbol{r}''(t)\|}{\|\boldsymbol{r}'(t)\|^3} =\frac{a}{a^2+b^2},\qquad a>0.\]

RDownload
cross3 <- function(a, b) {
  c(a[2]*b[3]-a[3]*b[2],
    a[3]*b[1]-a[1]*b[3],
    a[1]*b[2]-a[2]*b[1])
}
a <- 2; b <- 0.5
rprime <- function(t) c(-a*sin(t), a*cos(t), b)
rsecond <- function(t) c(-a*cos(t), -a*sin(t), 0)
curvature <- function(t) {
  v <- rprime(t); acc <- rsecond(t)
  sqrt(sum(cross3(v,acc)^2))/(sum(v^2)^(3/2))
}
times <- seq(0, 2*pi, length.out = 100)
kvals <- vapply(times, curvature, numeric(1))
range(kvals)
stopifnot(max(abs(kvals - a/(a^2+b^2))) < 1e-10)

The constant curvature is a property of this helix, not of arbitrary parametrized curves. For a general curve, verify regularity (\(\boldsymbol{r}'(t)\ne0\)) before applying the curvature formula. Numerical differentiation of sampled positions requires additional attention to noise and step size.

Extended worked laboratory 3: numerical gradient descent

For the strictly convex quadratic \(f(x,y)=\tfrac12(4x^2+2y^2)\), the gradient is \((4x,2y)\). Gradient descent with constant step size \(\eta\) is \(\boldsymbol{x}_{k+1}=\boldsymbol{x}_k-\eta\nabla f(\boldsymbol{x}_k)\). For this quadratic, the iteration converges to the origin when \(0<\eta<2/4=1/2\).

RDownload
f <- function(p) 0.5*(4*p[1]^2 + 2*p[2]^2)
grad <- function(p) c(4*p[1], 2*p[2])
eta <- 0.2
p <- c(3, -2)
history <- matrix(NA_real_, nrow = 31, ncol = 3)
colnames(history) <- c("x", "y", "objective")
for (k in 0:30) {
  history[k+1, ] <- c(p, f(p))
  if (k < 30) p <- p - eta*grad(p)
}
plot(0:30, history[, "objective"], type = "b",
     xlab = "Iteration", ylab = "Objective value")
stopifnot(tail(history[,"objective"],1) < 1e-8)
Experiments.

Repeat with \(\eta=0.49\) and \(\eta=0.55\). Compare convergence and divergence. Explain why a step size that works for one objective function need not work for another. This exercise connects Hessian eigenvalues, optimization geometry, and numerical algorithm design.

Extended worked laboratory 4: a density-weighted centroid

Let a thin rectangular plate occupy \(0\le x\le2\), \(0\le y\le1\), with density \(\rho(x,y)=1+x\). Its mass is \[M=\int_0^2\int_0^1(1+x)\,dy\,dx=4.\] Its centroid is \((\bar x,\bar y)\), where \(\bar x=M^{-1}\iint_D x\rho\,dA\) and \(\bar y=M^{-1}\iint_D y\rho\,dA\). Analytically, \(\bar x=7/6\) and \(\bar y=1/2\).

RDownload
rho <- function(x,y) 1+x
inner_y <- function(x, integrand) {
  vapply(x, function(xx) {
    integrate(function(y) integrand(xx,y), 0, 1)$value
  }, numeric(1))
}
double_int <- function(integrand) {
  integrate(function(x) inner_y(x,integrand), 0, 2)$value
}
M <- double_int(rho)
Mx <- double_int(function(x,y) x*rho(x,y))
My <- double_int(function(x,y) y*rho(x,y))
centroid <- c(xbar = Mx/M, ybar = My/M)
print(centroid)
stopifnot(abs(M-4)<1e-7)
stopifnot(max(abs(centroid-c(7/6,1/2)))<1e-7)
A mathematical check.

The centroid must lie inside the plate. Because density increases with \(x\), its horizontal coordinate should exceed the geometric center \(x=1\). Symmetry in the \(y\) direction forces \(\bar y=1/2\). These qualitative checks are as important as the numerical comparison.

Extended worked laboratory 5: reproducible numerical experiments

Numerical experiments should separate model parameters, computational methods, and output. Here we investigate the convergence of the centered-difference derivative of \(\sin x\) at \(x=1\).

RDownload
centered <- function(h) (sin(1+h)-sin(1-h))/(2*h)
h <- 10^seq(-1, -7, by = -1)
approximation <- vapply(h, centered, numeric(1))
error <- abs(approximation-cos(1))
results <- data.frame(h = h, estimate = approximation,
                      absolute_error = error)
print(results, digits = 8)
plot(h, error, log = "xy", type = "b",
     xlab = "Step size h", ylab = "Absolute error")
Interpretation.

Over a range of moderately small step sizes, the centered-difference truncation error decreases approximately as \(h^2\). At very small steps, floating-point cancellation may prevent continued improvement. When comparing methods, specify the exact function, evaluation point, error metric, and computing environment.

Extended worked laboratory 6: reading, cleaning, and plotting measurements

A small observational data set can be created within a script so the example is fully reproducible. Suppose temperature is measured at five equally spaced positions and one measurement is missing.

RDownload
measurements <- data.frame(
  position = seq(0, 2, by = 0.5),
  temperature = c(20.1, 21.0, NA, 23.2, 24.1)
)
write.csv(measurements, "results/temperature.csv",
          row.names = FALSE)
reloaded <- read.csv("results/temperature.csv")
stopifnot(nrow(reloaded) == 5)
valid <- complete.cases(reloaded)
plot(reloaded$position[valid],
     reloaded$temperature[valid], type = "b",
     xlab = "Position (m)", ylab = "Temperature (degrees C)")
Interpretation.

The line between the observed points is a visualization, not proof of a linear physical relationship. Do not silently replace a missing measurement with a zero. If an interpolation is scientifically justified, state the method and distinguish measured from estimated values.
